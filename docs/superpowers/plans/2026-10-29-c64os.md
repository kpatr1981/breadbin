# c64os Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A bootable `c64os.d64` for VICE: a preemptive multitasking Unix-like kernel with a directory filesystem on the 1541, a shell, pipes and separate command executables.

**Architecture:** ca65 kernel at $A000–$CFFF with BASIC banked out and KERNAL ROM kept for IEC/screen. Non-preemptible kernel, preemptible user mode; context switch saves ZP $02–$3F and the used part of the stack page per process. Programs are page-relocatable `CX` executables produced on the host by assembling twice ($0000/$0100 origins) and diffing. A Python tool builds the hybrid CBM-DOS + c64fs disk image.

**Tech Stack:** ca65/ld65 (cc65), Python 3 (stdlib only), c1541 for sanity checks, VICE 3.10 `x64sc` with remote monitor for automated tests, make.

**Spec:** `docs/superpowers/specs/2026-10-29-c64os-design.md`

## Global Constraints

- Stock C64 + 1541 must always work; REU is optional, detected at boot.
- No commands faked inside the shell; only `cd` and `exit` are built-ins.
- No `fork()`; `spawn()` instead.
- Text is ASCII inside the system (`\n` = $0A); the console driver converts to/from PETSCII and runs the screen in lowercase charset.
- Host tooling uses only the Python standard library.

## Fixed decisions (ABI — every task uses these)

**Memory (stock):** $01=$36. ZP $02–$1F kernel args/scratch (swapped per process), $20–$3F user ZP (swapped), $40–$8F kernel globals (not swapped). User page pool $08–$8F (136 pages). Kernel code/data $9000–$CEFF. Syscall jump table at $CF00, 3 bytes per entry.

**Syscall convention:** `jsr $CF00+3*n`. Args: A, X, Y, `r0`=$02/03, `r1`=$04/05, `r2`=$06/07. Return: carry clear = ok, carry set = error with A=errno. Include file `include/c64os.inc` defines `SYS_*` labels, `r0..r2`, `O_*`, `E*`, `SIG*`.

Opening a directory and `read()`ing it returns raw 16-byte entries. stderr: children get fd 2 = parent's fd 2 (shell's console). MAXPROC = 12. Shell built-ins: cd, exit, kill.

**Errnos:** ENOENT 2, EIO 5, EBADF 9, ENOMEM 12, EEXIST 17, ENOTDIR 20, EISDIR 21, EINVAL 22, EMFILE 24, ENOSPC 28, ENOTEMPTY 39, ENAMETOOLONG 36, ECHILD 10, ESRCH 3, EPIPE 32, ENOEXEC 8.
**Signals:** SIGINT 2, SIGKILL 9, SIGTERM 15, SIGPIPE 13 — default action terminate (exit code 128+sig).

**Program entry:** image offset 0. ZP $20/$21 = argv, $22 = argc. Returning (RTS) from entry = exit(0).

**CX executable format:** `"CX"`, version 1, image size (2), bss size (2), reloc count (2), image bytes, reloc offsets (2 each; add load page to byte at offset).

**c64fs layout:** linear block b = index in standard d64 order. Track 18 reserved for CBM DOS. Superblock at block 376 (T19 S0): `"C64FS"`, ver 1, nblocks(2), ninodes(1)=128, bitmap block(2), inode start(2), inode blocks(1)=16, root ino=1. Bitmap: 1 block, bit set = used. Inode 32 bytes: type(0 free,1 file,2 dir,3 chardev), nlink, size(3), major, direct[12](2 each), indirect(2). Dir entry 16 bytes: ino(1, 0=free), name(15, NUL-padded, max 14 chars). Devices: major 0 null, 1 console.

## Review Focus

1. Ctrl-C (RUN/STOP) while a command is blocked on a pipe or console read — must terminate it and free memory/fds, shell prompt returns.
2. `ls | head -2` — reader exits early; writer must get SIGPIPE, not hang.
3. Disk full / inode table full on write or mkdir — ENOSPC, no corrupted fs.
4. Spawn when memory is exhausted — ENOMEM error message, no crash, shell survives.
5. Paths with trailing slash, `..` at root, names longer than 14 chars.
